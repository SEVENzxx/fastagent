# FastAgent 需求文档（当前版）
> 更新日期：2026-07-02  
> 本文档基于 2026-05-28 版需求文档和当前项目实现整理。需求口径以当前代码已经完成的能力为主，保留适合继续完善的产品需求，不延续与当前架构不一致的设想。

---

## 1. 产品定位

FastAgent 是面向电商与客服场景的多租户智能客服系统。系统通过 Web 管理后台、实时会话工作台、企业微信渠道、知识库、商品库、订单系统和 AI 场景助手，帮助企业完成客户咨询接待、商品推荐、订单处理、知识问答、售后转接和平台运营管理。

当前产品不以开放式 Agent Planner 为核心，而采用更可控的架构：

```text
业务会话入口
  -> AI 入站处理管线
  -> AssistantService 主编排
  -> ContextResolver / RecognitionPipeline
  -> 场景 Handler
  -> Skill / RAG / LangGraph 子图
  -> 回复落库与实时广播
```

产品目标：

1. 提升客服响应效率：AI 处理常规咨询，人工可接管复杂或高风险会话。
2. 降低知识检索成本：将 QA、文档、商品知识、营销资料和图片沉淀为可检索资产。
3. 支持销售闭环：商品推荐、订单创建、订单查询、取消、售后和客户跟进形成闭环。
4. 支持 SaaS 化运营：多租户隔离、RBAC、平台 Admin、套餐、模型池、用量与审计。
5. 保证可控与可审计：写操作经过场景权限、Pending、图流程和审计边界约束。

## 2. 当前产品边界

### 2.1 当前已进入产品基线

- 单一 Vue SPA 同时承载租户端和平台 Admin，通过路由和权限隔离。
- FastAPI 后端提供 REST API、WebSocket、企业微信 Webhook、AI 内部链路和开发/测试内部接口。
- AI 助手以 29 个 `scenario_id` 为核心，覆盖商品、订单、知识、记忆、模板和转人工。
- 订单写操作使用 LangGraph 子图和 Redis Pending 恢复。
- 知识库使用 PostgreSQL 元数据 + Qdrant 向量检索 + LLM 摘要。
- LLM 用量有日志、后台 flush 和基础看板。
- 平台 Admin 已具备租户、套餐、LLM 配置、跨租户业务查询、系统配置、备份记录和数据库健康基础能力。

### 2.2 当前不作为主线的需求

- 不拆独立 Admin 前端工程，继续使用同一 Vue SPA。
- 不采用通用 DSL 或通用 Agent Planner 自动执行所有场景，复杂流程写在 Handler 和 LangGraph 子图中。
- Web 客户聊天页、公众号渠道、MaxKB 同步、企业微信扫码登录属于后续增强，不影响当前产品闭环。
- AI 自动跟进可以作为增强，但必须先补齐发送窗口、冷却、退订、敏感词和审计约束。

## 5. 核心业务流程需求

### 5.1 客户咨询到 AI 回复

1. 客户消息通过企业微信 Webhook、会话 API 或开发测试通道进入系统。
2. 系统识别租户、联系人和会话，创建消息记录。
3. `entry/processor.py` 根据会话状态过滤关闭、人工接待、非文本等情况。
4. 可由 AI 处理时，进入 `AssistantService`。
5. `AssistantService` 先处理 Pending，再处理上下文解析和场景识别。
6. 场景 Handler 调用 Skill、RAG 或 LangGraph 子图生成结果。
7. `_finalize()` 校验权限、保存 Pending/SessionContext，输出 `AssistantRuntimeResult`。
8. Processor 将 AI 回复落库并通过 WebSocket 广播。

验收重点：普通咨询必须有稳定回复；高风险和强规则场景必须可转人工；写操作不能绕过 Pending 和权限规则。

### 5.2 人工接待与排队

当前已支持基础转人工：

1. AI 命中 `human.transfer` 或 Pending 中用户要求人工时，返回转人工话术。
2. Processor 消费 `requires_human_handoff`，将会话标记为待人工。
3. 人工排队中客户会收到排队提示。
4. 客户回复“智能客服”可切回 AI 处理。

待完善：坐席自动分配、队列池、主管转派、超时升级、转人工通知、处理 SLA 和审计。

### 5.3 商品咨询与推荐

当前已支持：

- 商品分类浏览。
- 条件筛选和语义推荐。
- SKU/货号查询。
- 商品详情、属性、适用场景咨询。
- 商品对比、翻页和排序。
- 基于 `SessionContext` 的序号选择和指代追问。

需求边界：

- 商品详情必须先确定商品身份，再查商品数据和商品知识。
- 商品列表结果必须写入 `last_visible_products`，支持“第一个”“下单第一款”。
- 商品推荐不能直接生成事实性卖点，知识增强内容必须来自商品知识或商品详情。

### 5.4 订单查询与订单操作

当前已支持：

- 订单列表、筛选、详情、物流状态查询。
- 订单创建、更新、状态流转、批量状态更新和删除 API。
- AI 下单、取消、售后/退款使用 LangGraph 子图。
- Pending 恢复、取消、转人工和重复提交防护。

需求边界：

- 订单查询必须基于 `contact_id` 和 `tenant_id`，不能泄露其他客户订单。
- 创建、取消、确认、售后是写操作，必须通过图流程和 Pending 恢复。
- 售后自动写入能力已存在，但常见退款关键词当前可能优先转人工，需要在产品策略上明确是否自动进入售后图。

### 5.5 知识库与 RAG

当前已支持：

- 知识文档上传、解析、分块、向量化。
- QA 问答对管理和检索。
- 商品知识问答。
- 命中测试。
- 多条或长内容命中时使用 LLM 摘要。

需求边界：

- 无知识命中时不编造答案。
- 知识回答后保存 `last_knowledge_refs`，支持追问。
- 商品知识问答需要焦点商品或明确商品上下文。

### 5.6 销售智能与客户跟进

当前已支持基础数据能力：

- 客户 360 聚合视图。
- 销售阶段和客户商品上下文。
- 销售记忆。
- 会话待办。
- 跟进计划。
- 报价分档和低于底价标记。

待完善为完整产品能力：

- 自动跟进调度与发送。
- 跟进冷却时间、发送窗口、每日上限、退订识别。
- 低于底价报价审批流程。
- 主管视角的跟进管理和销售漏斗统计。

### 5.7 平台 Admin 与 SaaS 运营

当前已支持平台基础后台：

- 平台 Dashboard。
- 租户、套餐、LLM 配置管理。
- 创建租户时自动创建租户管理员和默认角色。
- 跨租户会话、消息、订单、知识文档查询。
- 系统设置、数据库健康、备份记录。
- 审计日志、登录历史、平台级敏感词、用量查询。

待完善：

- 高危操作二次确认和自动审计。
- 备份创建/恢复的真实执行策略和恢复演练。
- 套餐额度强约束和续费/加量流程。
- 平台运营报表和导出。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 多租户隔离 | 所有业务数据查询必须带 `tenant_id`；平台超管跨租户访问必须有独立权限和审计。 |
| 安全 | JWT、RBAC、密码哈希、API Key 加密、Webhook 签名校验、敏感词、高危操作审计。 |
| 可靠性 | Webhook 快速 ACK，异步处理失败可追踪；Redis/Qdrant/LLM 不可用时要有降级路径。 |
| AI 可控性 | 场景、Handler、Skill、PolicyGuard、Pending 边界必须清晰；写操作不得由 LLM 直接决定。 |
| 可观测性 | trace_id、结构化日志、LangFuse 可选观测、ResourceTrace、LLM 用量日志、Harness 报告。 |
| 性能 | 列表分页；会话和消息查询避免全量加载；AI 常规回复应优先走规则、SQL、QA 和短链路。 |
| 可维护性 | 新能力按 Model -> Schema -> Service -> API -> Frontend -> Harness 的顺序推进。 |
| 数据恢复 | 备份记录、恢复动作和高危维护操作必须可审计，恢复能力需要演练验证。 |

## 9. 验收标准

### 9.1 租户端

- 员工能登录并进入工作台。
- 工作台能展示会话、消息和实时 AI/人工回复。
- 租户管理员能维护员工、角色、权限、商品、分类、联系人、订单、知识、QA、图片和营销资料。
- 会话中可触发 AI 商品咨询、订单查询、知识问答和转人工。
- 所有租户数据受 `tenant_id` 隔离，普通员工不能访问平台 Admin 数据。

### 9.2 AI 助手

- 商品列表后“第一个”能进入详情，“下单第一款”能进入下单流程。
- 无上下文“确认/取消”不会触发写操作。
- 下单、取消、售后图流程能设置 Pending、恢复和取消。
- 知识问答无命中时不编造答案。
- 强规则转人工优先级高于普通识别。
- ResourceTrace 能反映 Skill、LLM、Vector 和 Pending 行为。

### 9.3 平台 Admin

- 超管能查看平台 Dashboard、租户、套餐和 LLM 配置。
- 超管能跨租户查询会话、订单、知识文档和用量。
- 高危平台操作需要审计记录。
- 系统设置、数据库健康和备份记录页面可用。

### 9.4 运营与安全

- 敏感词命中策略能区分 warn、transfer、block。
- LLM 用量能按租户记录并在看板查询。
- WebSocket 断开可重连；Redis pub/sub 可支持多实例广播。
- Harness 能覆盖核心 AI 场景和回归用例。

## 10. 与 2026-05-28 版需求的取舍

保留并已推进的方向：

- 多租户 SaaS、RBAC、平台 Admin、LLM 模型池、用量统计。
- 商品、客户、会话、订单、知识库、素材库和销售智能。
- 企业微信渠道、AI 自动回复、人工接管、知识检索和业务审计。

根据当前实现调整的方向：

- Admin 不拆独立前端工程，继续使用单一 Vue SPA。
- AI 主线从“分层意图 + 置信度门控混合 Agent”调整为“场景识别 + Handler + Skill + LangGraph 子图”。
- 复杂写流程不交给通用 Planner，而由明确的订单图和 Pending 机制处理。
- MaxKB、公众号、Web 客户聊天页、自助注册、扫码登录等作为后续扩展，不进入当前核心闭环。
- 自动跟进保留为产品方向，但必须先补齐风控、审计和退订机制。
